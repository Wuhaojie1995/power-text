### 踩到的坑（都已修）

1. **`camera.far = 6000` 把整个星系盘静默裁掉了**。盘中心在 z ≈ -6800，远端到 -9400，
   全在远平面外。症状极具误导性：**场景跑起来了、控制台一条报错都没有、画面上什么都没有**，
   太阳系（z≈-950）却正常显示。
   → 把 `three-scene.ts` 的 far 从 6000 提到 24000（near 保持 0.1）。
   深度精度跨了 24 万倍，但这些场景没有共面几何体，实测无副作用（starfield / lensing 回归正常）。
   **排查 3D 背景「什么都看不见」时，第一件事是核对相机 near/far 和物体的实际距离。**

2. **同一文件并行发多个 Edit 会互相覆盖**。一条消息里对 `galaxy.ts` 发了 5 个 Edit，
   全部返回成功，实际只有第一个（和部分）生效，后面的基于旧内容被丢弃。
   → 同一文件的编辑必须串行，或者合并成一次 Write。

3. **轨道环只建了几何和材质，忘了 new LineLoop 并挂进场景** —— 不报错，就是不显示。
   `THREE.Line` / `Points` / `Mesh` 这类渲染对象必须显式创建 + `add()`。

4. **光晕贴图的衰减曲线直接决定「光污染」**。第一版渐变（0.22→0.5、0.52→0.14）
   让太阳光晕在卡片上糊出一大片暖色；改成陡衰减（0.16→0.45、0.45→0.11）
   并收到 150 尺寸 / opacity 0.78 之后才「亮而不大」。

5. 轨道环 opacity 试了三档：0.17 读不出来、0.3 比行星还抢眼、**0.22 正好**。

### 关键实现手法

- **投影密度补偿**：盘面是斜的，近端深度只有远端的一半，均匀撒点会让近端稀得可怜。
  撒点走 rejection sampling，接受概率取 `(nearDepth / depth)²`，
  正好抵消屏幕面积随 `1/深度²` 的收缩 → 屏幕上密度均匀。
  `nearDepth = -DISC_Z - DISC_RADIUS * cos(DISC_TILT)`，是盘上离相机最近那条边的深度。
- **核球用 sprite 不用点云**：中心区域点密度天然极高，几百个加法混合的点叠在同一像素上
  必然烧成白饼。点云从 640 单位半径处才开始铺，最里面交给一张躺在盘面里的面片
  （`rotation.x = -PI/2` 翻到 XZ 平面，随盘倾斜后自然变成椭圆 —— 正是真实星系照片的形状）。
- **中心亮度额外衰减 0.34**：`bright *= 0.34 + 0.66 * min(1, rNorm / 0.26)`，
  这条是整套亮度的命门，去掉立刻糊。
- **太阳系用屏幕归一化坐标锚定**，不用世界坐标写死：
  `halfH = tan(fov/2) * SOLAR_DIST`，位置 = `(anchorX * halfW, anchorY * halfH, -SOLAR_DIST)`。
  再按 `aspect / 1.6` 缩放，`aspect < 1.2` 时锚点左移 —— 否则竖屏下横向可视范围只剩一半，
  太阳系会直接溢出右边界。
- 地球是唯一用自定义 shader 的星球：几组正弦叠出「大陆」斑块 + 菲涅尔边缘大气。
  一颗带蓝色亮边的球比一颗纯蓝球好认十倍 —— 15px 的球体光靠颜色区分不出是地球。

## 第二轮：太阳系重做（用户反馈「太阳系好好处理啊，看着都不行，太模糊了」）

用户没有给做法，只说「太模糊」。分两步走：先**诊断归因**，再改。

### 归因（这一步比改代码重要）

拆出四个叠加原因，按贡献排序：

1. **全部行星是 `MeshBasicMaterial`** —— 平涂、零光照。球体没有明暗，几十像素上就是贴纸。
2. **尺度太小** —— 地球屏幕直径只有 ≈16px。
3. **段数太低** —— `SphereGeometry(r, 20, 14)`。
4. **`antialias: false` + 走后处理链 ⇒ 完全没有 MSAA** —— 球边缘是硬阶梯，1px 轨道线呈虚线。

第 4 条是排查中发现的，也是最容易被忽略的：**只要走了 `EffectComposer`，
`renderer` 上的 `antialias: true` 就完全失效**（后处理先画到离屏纹理，那一步不享受默认帧缓冲的 MSAA）。

### 改动

`three-scene.ts`
- 新增 `MSAA_SAMPLES = 4`，`setupPost()` 里建带 `samples` 的 `WebGLRenderTarget`
  （`type: HalfFloatType`，尺寸取 `getDrawingBufferSize()`）传给 `EffectComposer`。
  `RenderTarget.copy()` 会带上 `samples`，composer 内部 ping-pong 的两份 target 都吃到 MSAA。

`galaxy.ts`
- `MeshBasicMaterial` → 自写朗伯光照 shader：`shade = uAmbient + pow(lambert, 0.85) * (1 - uAmbient)`，
  `SOLAR_AMBIENT = 0.14` 给暗面留轮廓。光照和菲涅尔用**视图空间**法线，
  表面条纹必须用**物体空间**法线（否则自转时条纹满球乱爬）。
- 新增 `createEarthMaterial` / `createRingMaterial` / `createSunMaterial`，
  以及共享的 `SolarUniforms`（六行星 + 月球 + 地球引用同一个 uniform 对象，一处 `copy()` 全生效）。
- 尺度：`SOLAR_DIST` 950→800、行星半径整体放大（地球 10→15、太阳 11→26）、
  段数按半径分级（`>= 12` 给 40×28，其余 28×20）、轨道环 128→256 段。

### 第三轮微调（同一天，放大截图后继续收）

第一版改完放大看，还有三处「糊」：

- **太阳是一块平白圆盘 + 一大团暖光糊在卡片上**。
  实测：光晕 sprite 118 尺寸罩在半径 25px 的日面上，边缘出现 **8~10px 过渡带**
  （4x MSAA 下本该 1~2px）；光晕在半径 200px 处还把亮度从背景的 8 抬到 21。
  改：光晕 118→88、opacity 0.78→0.58；`bloom.radius` 0.6→0.45；
  日面核心色 `#fff6dc`（亮度 0.96，整个球面都超辉光阈值）→ `#fff0b8`（~0.9）；
  临边昏暗指数 0.42→1.05（0.42 把衰减全挤在最外 15% 半径里）。
  ⚠️ **教训**：日面「像平白圆盘」的真凶是**光晕和 bloom radius**，不是临边昏暗 ——
  我一开始把功劳记在临边指数上，是径向剖面数据把我纠正回来的。
- **地球是「戴白帽的蓝球 + 波点云」**。极冠门槛 `|y| > 0.70`（= 北纬 45°）盖掉近半个球；
  云是单组三轴正弦相乘 —— 数学上就是**正交格子**，投到球面上是等间距白圆点。
  改：极冠门槛 0.70→0.88（61.6°）；海陆频率整体 ×1.6（22px 波长 → 14px）；
  云加第二组高频 + 相位错开；大气亮边指数 2.6→3.4、强度 0.8→0.5；地球光晕 62→46。
- **地球的云仍是方块** → 加**域扭曲**：`p = normalize(on + warp)`，warp 是三轴低频正弦 ×0.28。
  极冠**不跟着扭曲**（否则会飘到中纬度）。
- **太阳被底部数据卡切掉一块**：`SOLAR_ANCHOR_Y` -0.42→-0.28，整体上移约 63px。

### 光照方向的误判（值得记）

放大截图连着两轮都觉得「地球被左上照亮、太阳在右下 ⇒ 光照反了」。
写了个像素回归才确认是对的：取球面内像素做 `L = a + b·dx + c·dy` 最小二乘，
梯度方向即被照亮方向，与「球心→太阳」求余弦 = **+0.943**。
误判的原因：地球一个半球是绿色大陆、另一个是深蓝海洋，
**肉眼会把「大陆那半边」当成亮面**。教训：光照方向必须量，不能看。

### 顺带修的（与本次需求无关但会炸构建）

### 探针口径修正（verify-runtime.mjs）

加 MSAA 后 `bindFramebuffer(null)` 口径失真：MSAA 的 resolve 每帧多绑几次默认帧缓冲，
**一帧被数成 5 帧**，渲染 fps 虚高到 117.5（RAF 只有 60.5 —— 渲染 fps 高于 RAF fps 是物理上不可能的）。
改成在 RAF 包装里判断「这次回调有没有产生新的 bindFramebuffer」，新增 `renderedFrames`，
与 MSAA 无关；`frameTimes` 也从 bindFramebuffer 挪到 RAF 包装里。
报告新增自证项：打印 `bindFramebuffer 次数 / renderedFrames` 的倍数（实测 5.0，即 MSAA 生效）。
另外 `frameTimes` 换视口前要清空，否则跨视口累积会让 `min` 失去意义。

⚠️ 这次又被「模板字符串里的反引号」坑了一次 —— 但这次是在 **Node 脚本**里：
`verify-runtime.mjs` 的 `PROBE_SOURCE` 注释写了 `` `bindFramebuffer(null)` ``，
反引号把模板截断，脚本直接 `SyntaxError: Unexpected identifier`，连解析都过不了。
（第一轮那次是 GLSL 里的反引号导致 Vite 500。）**注释里一律不用反引号**。

## 首页禁止复制

需求原话：「首页得禁止复制，禁止出现 @image#1:Clipboard_Screenshot.png 这种情况」
（在浏览器外壳里框选首页文字再复制，落到剪贴板里的是一张选区截图，粘到聊天框就是一坨图）。

### 落地结果

只改了一处：`src/pages/Home/home.less` 的 `.home-page` 里加

```less
-webkit-user-select: none;
user-select: none;
-webkit-touch-callout: none;   // iOS 长按气泡
```

验收（`shoot-nav.mjs --eval` 读计算值）：`.home-page` 与 `.home-hero-role` 的
`user-select` 都是 `none`。登录弹窗不受影响 —— 它被 antd portal 到 `<body>`，
不在 `.home-page` 子树里。

### 走过的弯路（记住这个教训）

第一版加了 `useCopyGuard.ts`：原生监听 copy / cut / dragstart，另加「Ctrl+C 时
`navigator.clipboard.writeText('')` 主动清剪贴板」。**被武先生一句
「这不是一行 CSS 就可以解决的问题嘛」否掉，当场全撤。**

教训：**「禁止复制」在页面这一侧就是 `user-select: none` 一行的事。**
「剪贴板里残留的旧内容」不是页面的责任 —— 没有选区时浏览器压根不触发 copy 事件，
谁也拦不住上一次的剪贴板内容被粘出来。为一个不属于自己的问题加 JS 层，
是在给用户制造复杂度。

另外两条实测结论（诊断脚本已删，结论留档）：

- 无头 Chrome 里用 `Input.dispatchMouseEvent` 划选，**`mouseMoved` 必须带
  `button: 'left'` + `buttons: 1`** 才能选中；只给 `buttons: 1` 选不出来（基准页实测）。
  这条以后写选区相关的验收脚本还会用到。
- 对照组的做法：**先把目标元素的 `user-select` 内联改成 `text` 再拖一次**。
  否则「拖拽选不出东西」这个断言永远为真，等于没验。
