### 3. ⚠️ 发现并修掉一个真 bug：引力透镜的横向定位随宽高比漂移

**现象**：竖屏 480×900 下，黑洞和光子环**整个消失**，只剩一条横贯的吸积盘光带。

**根因**：shader 里 `p = (vUv - 0.5) * vec2(uResolution.x / uResolution.y, 1.0)`，
即纵向恒定 ±0.5、**横向是 ±宽高比/2，可视范围随宽高比变**。
而 `CENTER_X = 0.5` 是个写死的绝对值：

| 视口 | 宽高比 | 可视半宽 | c.x=0.5 落在 | 结果 |
| --- | --- | --- | --- | --- |
| 1440×900 | 1.60 | 0.80 | 81.3% 宽度 | 正常 |
| 2560×1080 | 2.37 | 1.185 | 71.1% 宽度 | 正常（但位置不一致） |
| 480×900 | 0.533 | **0.267** | **超出画面** | 黑洞整个消失 |

**修法**：改成「可视半宽的比例」`CENTER_X_RATIO`，`resize` 里更新 `halfWidth`，
再重算 `uCenter`。纵向不受影响（半高恒为 0.5），`CENTER_Y = 0.3` 保持绝对值。

**踩的第二个坑**：反推比例时我把参考视口当成了 16:9，算出 `0.5/(16/9/2) = 0.5625`——
但截图用的 1440×900 是 **16:10**。用 0.5625 会把本来要保住的 1440×900 画面整体左移 45px。
正确值 `0.5/(1.6/2) = 0.625`。

**验证手段也踩了坑**：一开始想「找全屏最亮像素」当光子环位置，连着两轮量到的都是
**白色登录卡片 / 卡片上的白色 logo**（全屏最亮的东西是卡片，不是发光体）。
而且排除掩码也没对准卡片（1440×900 下卡片实际占 x 27%~73%、y 34%~66%，
竖屏下比例完全不同），得出过完全错误的结论。
最后改用 **`ImageChops.difference` 差分**才拿到可信结论：

- 1440×900 修前 vs 修后：逐像素完全相同 83.82%，差异 >16 级的只有 0.23% 像素、
  集中在 34 行（3.8%）——就是吸积盘那条带 `uTime` 的动画条纹。
  **几何确实没动。**
- 竖屏 480×900：光子环出现在右上，上半个弧露在卡片外（修前完全没有）。
- 21:9：黑洞稳定在 81.25% 宽度处，各宽高比下相对位置一致了。

## 续：首页导航栏右上角「不协调」修复 + 导航项悬浮态重做

武先生指出两处：① 右上角那一块（两个工具按钮 + 主按钮）不协调、不好看；
② 导航项的 hover 太素，要「炫酷一点」。两处都在首页导航栏。

### ① 右上角：根因是「一个胶囊里套了两个带边框的圆」

先用 CDP 读计算样式确认，不是凭肉眼猜：

| 元素 | 改前 | 问题 |
| --- | --- | --- |
| `.home-tool-btn` | `background: rgba(255,255,255,.12)` + `border: rgba(148,163,184,.45)` + `box-shadow: 0 4px 16px` | 胶囊里又套两个按钮，**三套边界互相打架**，圆钮视觉重量还压过导航链接 |
| `.home-enter-btn` | `height: 38px` | 右侧胶囊是 40px，**差 2px**，两个圆角矩形并排就读成「没对齐」 |
| `.home-brand-mark` | `38×38` | 同一条栏里第三个高度值 |

**根因其实是「两个文件抢同一条规则」**：`.home-tool-btn` 的配色写在 `home.less` 的
`.home-theme-dark()` 里（工具栏归它管），`portfolio.less` 的 mixin 里又写了一遍
（注释写着「不要再描边、不要再投影」，但只写了 `color` 和 hover 的 `background`，
**没写 base 的 `background`/`border`/`box-shadow`**）。两个 mixin 编译后特异性相同
（都是 `.home-page .home-tool-btn`），调用顺序是 home → portfolio，所以 portfolio 的
hover 赢了、base 却漏了 —— 注释里的意图没落地。**删掉 portfolio.less 里那份重复定义，
让 home.less 独占**，问题消失。

改动：
- 工具按钮静止态：无底、无描边、无投影，只留图标（和导航链接同级）；hover / `is-open` 才给淡底
- 品牌方块、导航胶囊、主按钮统一 **40px** 一个高度；主按钮补 `inset 0 1px 0 rgba(255,255,255,.26)`
  内顶高光，和左上角 logo 用同一种材质（首尾呼应）
- 导航胶囊底从冷灰 `rgba(148,163,184,.07)` 换成带蓝的玻璃 `rgba(120,156,214,.09)` + 内顶高光
  （冷灰压在深蓝粒子云上显脏）
- `.home-nav` 的 `gap` 18px → **14px**（这个 gap 只作用在「右侧整块 ↔ 主按钮」之间，
  品牌块被 `margin-left:auto` 推开了，不受影响）

### ② 悬浮态：从「一块扁平蓝底」改成「光子环 + 光标光斑」

改前是 `background: rgba(96,165,250,.18)` —— 和导航胶囊自己那层淡底几乎同色，
悬浮了跟没悬浮一样。现在三层叠加：

| 层 | 实现 |
| --- | --- |
| 底色 | 链接自身 `background`，**比栏底更暗**（`rgba(6,11,26,.72)`）。暗底光斑才亮得出来 |
| 光斑 | `::before` + `radial-gradient(92px circle at var(--nav-x) var(--nav-y), …)` |
| 光子环 | `::after` + `conic-gradient` 被 `mask` 裁成 1px 环，绕胶囊跑（`padding:1px` + `mask-composite: exclude`） |

外加：文字提纯白、整颗胶囊抬 1px、环的入场 `scale(.86) → scale(1)` 配过冲缓动（读作「锁定」）。

**关键实现点（都写进代码注释了）**：
- 链接加 `position: relative; z-index: 0` 造层叠上下文，伪元素给 `z-index: -1`
  —— 负 z-index 子层画在「元素背景之上、文字之下」，正好把光压在字后面
- 伪元素必须 `pointer-events: none`，否则盖住链接会把 hover 自己顶掉（一进去就闪出来）
- 光标坐标：`pointerenter` 量一次 rect 存 ref，`pointermove` 纯做减法
  —— 每次移动都 `getBoundingClientRect()` 会强制同步布局，这页底下还跑着 three.js
- `--nav-arc` 用 `@property` 注册成 `<angle>` 才能逐帧插值；用 `var(--nav-arc, 0deg)` 兜底，
  万一浏览器不支持 `@property`，环仍是常亮的静态环
- 浅色主题单独一套（白胶囊 + 蓝色光斑 + 蓝色环），**不加任何文字阴影**（沿用既有约定）
- `prefers-reduced-motion` 下 `::after` 直接 `display: none`（停转的环像渲染残留）

## 续：导航栏改成三栏 + 与内容列对齐 + 主按钮换图标

武先生第二轮要求：品牌块和右侧块**要和下方内容对齐**、中间菜单**居中**、主按钮**去掉文字换图标**。

### 根因：导航内容的左右边缘和正文列根本不是同一条竖线

量出来才知道差多少（视口 1920）：导航栏用的是 `padding: 12px clamp(18px,5vw,56px)`
直接铺在整屏宽的 header 上，品牌块左边缘落在 **x=56**；
而下方 `.home-section` 是 `max-width:1180px; margin:0 auto` + 同一套内边距，
正文左边缘在 **x=426**。**差了 370px** —— 一条竖线上两个参照物，一眼就是歪的。

### 改法：导航栏拆成「整屏宽外壳 + 限宽内容列」

```less
.home-nav        { padding: 12px 0; }   /* sticky + 滚动态玻璃底仍要铺满视口 */
.home-nav-inner  { width:100%; max-width:1180px; margin:0 auto;
                   padding: 0 clamp(18px,5vw,56px);
                   display:grid; grid-template-columns: 1fr auto 1fr; }
```
限宽和内边距必须和 `.home-section` **逐字一致**，否则还是对不齐。

⚠️ **三栏必须用 grid 的 `1fr auto 1fr`，不能用 flex + space-between**：
两侧 1fr 等宽才能保证中间那栏的**中心**落在整行中心上；space-between 只是把剩余空间均分，
中间那块的宽度一旦不对称（菜单 + 分隔线 + 两个工具按钮，左边明显比右边"重"），居中就偏。
实测 space-between 下菜单中心偏右约 40px，肉眼一眼能看出来。

顺带删掉 `.home-nav-cluster` 上的 `margin-left: auto`（它和 grid 的 justify-self 打架）。
